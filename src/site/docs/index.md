# 量潮众包官网 — 设计

## 定位

众包平台的公开入口：展示「标准交易市场」定位——需求拆解为标准任务，执行方按量潮标准交付，验收准则兜底。

核心问题只有一个：**需求方为什么在这里发单、执行方为什么在这里接单？**

设计输入：`data/intention/qtcrowd`（众包工作意图）、`data/journal/qtcrowd/`（众包日志）、`data/profile`（业务档案）。

## 首页

### Hero

一句话说明平台定位，附锚点。

> 量潮众包：标准交易市场。
> 我们不判断谁好谁坏，我们验证谁的产品符合标准。

锚点：`需求拆解为标准任务 · 执行方按量潮标准交付 · 验收准则兜底`

### 交易方式

双入口卡片：需求方发单（拆解标准任务、发布竞价）、执行方接单（注册、按标准交付、沉淀信用）。

### 标准任务

首页核心区块。展示全部任务类型：类型标签 + 标题 + 场景说明。

### 与量潮数据的协同

筛选导流闭环：众包市场筛选执行方，达标者进入 qtdata 认证供应商池；导流闸门不放开。

### 联系

GitHub / 邮件，无表单；说明当前以试验田方式在第三方众包平台外发任务。

## 接单页 `/take`

- 为什么在量潮众包接单（标准即契约、信用资产、认证导流）
- 接单流程（注册 → 浏览 → 交付 → 验收 → 导流）
- 平台原则（不做低价悬赏、通用市场自由注册、复现即成熟）
- 当前状态（试验田阶段）

## 演进方向

1. **标准任务库**：任务模板与验收准则的公开展示，让「标准」可见可复用；
2. **qtcloud-crowd 接入**：静态说明转为真实平台入口（任务发布、竞价、验收）；
3. **信用公开页**：执行方信用记录与标准执行率，支撑导流信任；
4. **认证池导流**：qtdata 认证供应商池的展示与申请入口。
